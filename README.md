# Ubicacion Ruta

Web adaptable a movil para registrar la ubicacion del telefono manualmente o cada 5 o 10 segundos mientras esta visible. Incluye Screen Wake Lock para mantener encendida la pantalla en navegadores compatibles. Usa Supabase Auth y PostgreSQL con RLS y Leaflet con la capa World Street Map de Esri. Por defecto las lineas son segmentos entre puntos; el ajuste a calles es una estimacion opcional que debes solicitar y revisar antes de guardar.

## Preparar Supabase

1. En el proyecto, abre **SQL Editor > New query**.
2. Ejecuta el contenido de [supabase/schema.sql](supabase/schema.sql). Crea las tablas `rutas` y `puntos_ruta`, indices, permisos y politicas por usuario en una transaccion. Incluye la funcion `crear_ruta_manual` y permite precision GPS nula para puntos trazados: vuelve a ejecutarlo si ya tenias una version anterior. Renombra las tablas y columnas antiguas al espanol sin borrar los registros. Puede ejecutarse de nuevo. Si detecta tablas antiguas y nuevas a la vez, se detiene para evitar mezclar datos.
3. En **Authentication > URL Configuration**, configura **Site URL** con la URL HTTPS donde publiques la web. Anade tambien esa URL a **Redirect URLs** para confirmacion de correo y recuperacion de contrasena. Durante desarrollo puedes anadir la URL HTTPS del puerto reenviado de Codespaces.
4. En **Authentication > Providers**, manten habilitado Email. Deja activada la confirmacion de correo. El servicio de correo de prueba de Supabase tiene limites y puede restringir destinatarios; para uso real configura SMTP propio si hace falta.
5. Crea tu cuenta desde la app y confirma el correo. Las credenciales de esta cuenta son independientes de las del panel de Supabase.

La URL y la clave publicable del proyecto estan en [src/principal.js](src/principal.js). Son datos publicos para el navegador, no claves administrativas. Nunca pongas claves `service_role`, `sb_secret_` o contrasenas de PostgreSQL en la web. RLS y los permisos SQL son los que protegen las ubicaciones. El esquema no concede acceso anonimo y usa una clave foranea compuesta para impedir puntos asociados a rutas de otro usuario.

Los nombres propios de variables, funciones, tablas y columnas se escriben en espanol: `estado`, `cargarRutas`, `usuario_id`, `latitud`, `longitud`, `precision`, `registrado_en` y `creado_en`. Los identificadores de APIs externas, como `auth.users`, `email`, `password`, las coordenadas de Geolocation y las claves obligatorias de GeoJSON conservan sus nombres oficiales.

## Desarrollo

Requiere Node.js 22.12 o superior.

```sh
npm install
npm test
npm run dev
```

Vite muestra el puerto disponible. En Codespaces, usa la direccion HTTPS del puerto reenviado para probar en el telefono. Este enlace de desarrollo solo funciona mientras Codespaces y el servidor esten activos: no es alojamiento permanente.

## Publicar sin depender del PC

En Vercel o Netlify, importa este repositorio, selecciona Vite, comando `npm run build` y directorio de salida `dist`. No requiere backend propio. Usa la URL HTTPS gratuita asignada y actualiza las URL de Supabase descritas arriba. La publicacion y cualquier coste o limite del proveedor quedan bajo tu cuenta. No hay despliegue automatico configurado en este repositorio.

## Uso y limitaciones

- **Proteccion contra rodeos al seguir calles:** se valida cada par consecutivo de puntos de paso, no la ruta global, para conservar idas y vueltas en U sin aceptar vueltas a la manzana como sustituto. Se rechaza toda la propuesta si un vertice se aleja mas de **25 m** del segmento original de ese par, o si su longitud supera **el doble de la distancia directa mas 30 m**. Se senalan los dos puntos afectados y el borrador permanece intacto. Son limites conservadores, no una garantia de la calle correcta: una esquina grande o curva real tambien puede rechazarse si faltan muestras intermedias. Si OSRM no permite una vuelta en U por restricciones del automovil, no se inventa otra conexion; usa **Acercar puntos a calles** o revisa los puntos. Match limita ahora el radio enviado a **25 m** (minimo 5 m), incluso con precision GPS peor; puede rechazar puntos imprecisos en vez de enviar radios grandes al servidor publico. Un `TooBig` por radio se explica como tal, sin atribuirlo al numero de puntos.

- La navegacion separa **Mapa**, para consultar y exportar recorridos; **Crear ruta**, para trazar desde el PC; y **Tomar ubicacion**, una pantalla vertical de captura sin mapa. Puedes abrirlas directamente con `?vista=mapa`, `?vista=manual` y `?vista=captura` en la URL de la app.
- En **Crear ruta**, inicia sesion, escribe el nombre y haz clic en el mapa para colocar puntos en orden. Los puntos se numeran y se unen con segmentos rectos; no se ajustan a calles ni calculan navegacion. Puedes deshacer el ultimo punto, borrar el borrador con confirmacion y encuadrarlo.
- En **Mapa** y **Crear ruta**, cada punto aparece numerado y cada segmento tiene una flecha del punto 1 al 2, del 2 al 3 y asi sucesivamente. Las rutas guardadas siguen el orden de fecha de registro (y de identificador cuando coinciden las fechas); el borrador sigue el orden de los clics. La lista y las ventanas de los puntos guardados indican inicio, siguiente punto y fin. Si dos puntos consecutivos coinciden, conservan sus numeros pero no se dibuja una flecha sin direccion. El sentido se calcula localmente, sin pagos, claves ni consultas externas de coordenadas; no incluye direcciones de calles ni navegacion vial.
- **Editar ruta** abre una vista previa rosa sobre la ruta activa original en gris. Puedes arrastrar cualquier punto, moverlo por coordenadas con **Mover**, eliminarlo de la lista o agregar puntos al final haciendo clic en el mapa. Tambien puedes mover y eliminar puntos de rutas nuevas. **Cancelar edicion** descarta el borrador sin cambiar la ruta activa. Puedes volver a Mapa sin perder el borrador; mientras editas se bloquean el cambio de ruta y la captura GPS. Cerrar o recargar pierde los cambios no guardados, con aviso previo cuando el navegador lo permita.
- **Guardar cambios** reemplaza los puntos de la ruta, pero guarda su nombre y puntos anteriores en `versiones_ruta` como respaldo inactivo, en la misma transaccion. Ejecuta la version actual de [supabase/schema.sql](supabase/schema.sql) antes de usar el editor. Si falla el guardado, no se modifica la ruta ni se crea un respaldo incompleto, y el borrador se conserva. Si otro dispositivo cambio los puntos desde que abriste el editor, el guardado se rechaza: cancela y actualiza antes de volver a editar.
- Las coordenadas editadas o ajustadas son estimaciones: se guardan sin precision GPS y con fechas nuevas de guardado, separadas por un milisegundo para conservar su orden. Las horas y precisiones originales quedan en el respaldo. **Ver respaldos inactivos** lista las versiones anteriores; abrir una renueva su fecha de consulta y permite verla, editarla o pulsar **Restaurar version**. Restaurar sin modificar conserva las coordenadas, horas y precisiones de ese respaldo y respalda la version activa reemplazada. Editar el respaldo antes de guardarlo lo convierte en una nueva edicion manual.
- **Ajustar a calles** abre el editor de la ruta activa. **Ajustar recorrido a calles** trabaja sobre el borrador actual. Solo tras confirmar se envian sus coordenadas, precisiones y horas (cuando son aptas) a [OSRM Match](https://project-osrm.org/docs/v5.24.0/api/#match-service). Se agrupan puntos consecutivos a menos de **10 metros**, comparando con el ultimo conservado, sin buscar coincidencias globales: se mantienen las segundas pasadas por una calle. Movimientos o giros menores de ese umbral pueden perder detalle. La agrupacion no cambia la ruta activa antes de guardar ni elimina vertices de la geometria devuelta.
- **Acercar puntos a calles**, en el editor, ofrece una alternativa cuando Match no reconoce el recorrido GPS. Tras confirmar el envio a OSRM Nearest, mueve cada punto a la calle de automoviles mas cercana, hasta **100 metros**, conservando todos los puntos y su orden (entre 2 y 100, sin agrupar). Hace una consulta por punto, separadas al menos 1.1 segundos y compartiendo el limite de consultas con Match; una ruta de 59 puntos puede tardar mas de un minuto. No exige confianza de Match, no calcula un camino entre puntos y no garantiza la calle correcta: podria elegir una calle paralela. Los segmentos siguen siendo rectos y pueden cortar esquinas. Si cualquier punto falla o supera el limite, no aplica ningun cambio. **Cancelar ajuste** tambien conserva el borrador previo. Al completar, muestra la propuesta rosa sobre la ruta original gris al editar; revisa y mueve puntos si hace falta antes de **Guardar cambios** o **Guardar ruta**. El guardado usa el flujo normal con respaldo al editar, sin precision ni horas GPS ficticias.
- **Seguir calles y quitar puntos cercanos** agrupa puntos consecutivos a menos de **10 metros** respecto al ultimo conservado, manteniendo inicio y fin. No elimina coincidencias globales: conserva visitas posteriores a la misma calle. Envia los puntos de paso en su orden a OSRM Route para proponer un camino de automovil y utiliza su geometria completa, incluidos vertices en curvas y esquinas aunque no hubiera una muestra GPS alli. Solo elimina vertices exactamente identicos consecutivos de esa geometria: no vuelve a agruparla a 10 m, lo que cortaria esquinas. El numero final de puntos puede crecer para representar las curvas; la vista previa informa cuantos puntos originales se agruparon, cuantos puntos de paso quedaron y cuantos vertices tiene la propuesta. Admite hasta 10000 puntos originales, de 2 a 100 puntos de paso tras agrupar, y hasta 10000 vertices finales (500 al crear una ruta nueva). Consulta tramos de hasta 10 puntos compartiendo un extremo, al menos 1.1 segundos entre peticiones y con el mismo limite de consultas que los otros ajustes. Verifica los puntos de paso en orden, la geometria y la coincidencia exacta entre tramos; si falla o se cancela, conserva todo el borrador sin conexiones rectas de emergencia. Cada punto debe encontrar calle a no mas de 100 m. Respeta las restricciones del perfil de automovil, por lo que puede elegir rodeos o calles diferentes; no reconstruye con certeza el recorrido GPS ni garantiza alineacion exacta entre el mapa Esri y las calles OpenStreetMap de OSRM. Revisa la propuesta rosa sobre el original gris al editar y pulsa **Guardar cambios** solo si es correcta. Se guardan tambien los vertices nuevos usando el flujo existente con respaldo; no se modifica la ruta activa solo por generar la vista previa. Mover puntos despues puede volver a crear segmentos rectos: genera de nuevo la propuesta para recalcularlos.
- El ajuste usa el perfil de automovil del [servidor de demostracion de OSRM](https://github.com/Project-OSRM/osrm-backend/wiki/Demo-server), solo para pruebas no comerciales razonables. Su limite es **1 solicitud por segundo en total**, sin garantia de disponibilidad, latencia ni actualizacion. Usa una sola sesion de prueba a la vez: la aplicacion limita consultas por sesion y reutiliza resultados en memoria, pero no coordina trafico de multiples usuarios. No lo uses como servicio publico de produccion; para ello configura un servidor propio/proveedor y adapta el endpoint en [src/ajuste.js](src/ajuste.js). No hay consultas automaticas durante la captura. Los datos de calles son de OpenStreetMap, con atribucion visible.
- El ajuste admite de 2 a 100 puntos tras agrupar y hasta 10000 vertices de resultado (500 al crear una ruta nueva). El servidor publico probado limita Match a **10 puntos por consulta**: se procesan tramos de hasta 10, compartiendo 3 puntos entre tramos y esperando al menos 1.1 segundos entre consultas. Solo se unen cuando coinciden el punto central exacto y la geometria interior compartida en el mismo orden; se tolera hasta 1 metro de diferencia de ajuste en los extremos compartidos, sin crear segmentos para unirlos. Solo se eliminan vertices exactamente identicos consecutivos del resultado, nunca las segundas pasadas. Si las zonas compartidas no coinciden, se rechaza el resultado. El progreso indica el tramo actual y **Cancelar ajuste** interrumpe las consultas conservando el borrador previo.
- Se rechazan resultados con puntos omitidos, tramos separados, geometria invalida o confianza OSRM inferior a 0.5, conservando el borrador anterior sin aplicar resultados parciales. Los errores HTTP muestran el codigo y detalle de OSRM (por ejemplo `NoMatch` o `TooBig`), no se presentan todos como una caida del servicio. El indicador de confianza es del algoritmo, no una garantia ni una precision GPS. Revisa siempre la vista previa; no incluye nombres de calles ni instrucciones de navegacion.
- Si OSRM no puede verificar el recorrido, el editor explica la causa y senala en azul intenso con doble borde los puntos sin correspondencia, los extremos de una separacion o el tramo de confianza insuficiente, por encima de los marcadores rosas. La leyenda explica ambos colores; la lista tambien los resalta con borde azul y texto, y los marcadores tienen una etiqueta accesible de revision. Son puntos para revisar, no cambios aplicados ni errores GPS demostrados; puedes usar **Mover** para inspeccionarlos. Las marcas desaparecen al modificar el borrador y se recalculan al volver a ajustar. No se eliminan puntos ni se usa un calculo de ruta alternativa para forzar una conexion. Solo se envian horas cuando todos los puntos consultados tienen precision GPS y tiempos estrictamente crecientes: las fechas de guardado de rutas manuales o editadas no representan velocidades reales.
- **Guardar ruta** requiere entre 2 y 500 puntos. La funcion SQL guarda la ruta y todos sus puntos en una unica transaccion con los permisos del usuario; si falla, no deja una ruta incompleta y la interfaz conserva el borrador para reintentar. Los borradores permanecen al cambiar de apartado, pero no se guardan en el navegador: cerrar o recargar la pagina puede perderlos, con aviso previo cuando el navegador lo permita. Cerrar sesion los descarta.
- Los puntos trazados se muestran como **Manual**, tienen precision nula (no una precision GPS ficticia) y fechas del guardado separadas por un milisegundo para conservar el orden de los clics. Estas fechas no representan horas de paso por cada lugar. Pueden consultarse y exportarse como las demas rutas.
- En **Tomar ubicacion**, inicia sesion, crea o selecciona una ruta y concede permiso de ubicacion al navegador. El contador muestra el total de puntos guardados en esa ruta, incluidos los de registros anteriores; no cuenta posiciones que aun no se han guardado.
- **Registrar ubicacion** guarda un punto manualmente desde esa misma pantalla.
- Cada pulsacion guarda un punto, su hora y su precision. No registra en segundo plano ni con la pantalla apagada.
- Para registro automatico, elige **Cada 5 segundos** o **Cada 10 segundos** y pulsa **Activar**. Registra un primer punto inmediatamente y programa los siguientes sin superponer solicitudes GPS. El intervalo es aproximado y puede alargarse si GPS o red tardan.
- **Mantener pantalla encendida** solicita Screen Wake Lock durante el registro automatico. El estado confirma si se obtuvo o muestra que el bloqueo no esta disponible. Puede fallar por permisos, ahorro de bateria o incompatibilidad. Consume mas bateria y no impide el bloqueo con el boton fisico.
- **Desactivar**, volver a **Mapa**, ocultar la app, perder conexion, un error o el cierre de sesion interrumpen el seguimiento y liberan la pantalla. Al volver a la captura debes pulsar **Activar** de nuevo; no se reanuda sin tu accion. Si Android libera el bloqueo mientras la app sigue visible, tambien se detiene el registro.
- Una posicion GPS pendiente se descarta al desactivar. Una peticion de guardado que ya se envio a Supabase puede terminar; no se puede deshacer desde el boton Desactivar.
- El manifiesto incluye iconos de Android y modo independiente. En Chrome para Android, abre la URL HTTPS y usa **Anadir a pantalla de inicio / Instalar aplicacion**, segun la version. No hay cache sin conexion ni servicio de ubicacion en segundo plano; instalar no elimina estas limitaciones.
- Necesita Internet para guardar en Supabase y cargar el mapa. No hay cola sin conexion; un fallo se muestra y no se anuncia como guardado.
- **Actualizar rutas** carga los cambios hechos desde otro dispositivo. **Exportar** descarga GeoJSON con los puntos y, cuando hay al menos dos, una linea.
- Eliminar una ruta elimina tambien sus puntos, tras confirmacion. No hay papelera.
- La sesion se conserva en este navegador. Cierra sesion en equipos compartidos y protege los archivos exportados.
- El navegador solicita mapas a Esri y fuentes a Google Fonts; estos proveedores reciben solicitudes de red. Solo si confirmas el ajuste se envian los puntos del borrador a OSRM, no el resto de tus rutas ni los respaldos. Se muestran los creditos de los proveedores en el mapa.
- El mapa usa la capa publica World Street Map de Esri, sin claves incluidas en la app. No hay garantia de disponibilidad ni de acceso gratuito permanente: revisa las condiciones y limites de Esri antes de distribuir la app o aumentar su uso. No se usa el servidor comunitario de mosaicos OpenStreetMap que devolvia el bloqueo 403.
- Si falla una imagen del proveedor, aparece un aviso con **Reintentar mapa**. El fallo del mapa no borra ubicaciones ni cambia los permisos de Supabase.

## Caducidad de respaldos inactivos

Despues de ejecutar [supabase/schema.sql](supabase/schema.sql), ejecuta [supabase/caducidad.sql](supabase/caducidad.sql) en SQL Editor como administrador. Requiere que Supabase permita habilitar `pg_cron`. Programa una limpieza diaria a las 03:15 UTC que elimina solo los respaldos cuya ultima consulta fue hace mas de **un mes calendario**. La ruta activa no caduca. Abrir o restaurar un respaldo reinicia el plazo; solo listar los respaldos no lo reinicia. Cada edicion crea un nuevo respaldo con un nuevo plazo. Si eliminas una ruta, sus respaldos tambien se eliminan.

La programacion puede ejecutarse nuevamente sin duplicar la tarea. Verifica su instalacion con `select jobid, jobname, schedule, active from cron.job where jobname = 'eliminar-versiones-rutas-caducadas';` y sus ejecuciones en `cron.job_run_details`. Si no instalas esta tarea, los respaldos **no se borran automaticamente**. El borrado de un respaldo caducado es definitivo; conserva una exportacion privada si necesitas retencion mas larga.

## Verificacion

```sh
npm test
npm run build
npx playwright test
```

Las pruebas unitarias verifican coordenadas, GeoJSON, agrupacion consecutiva de 10 metros, ajuste con tramos solapados, errores y cancelacion, y el ciclo de seguimiento y bloqueo de pantalla. Las pruebas SQL usan PostgreSQL embebido (PGlite) para comprobar creacion, ejecucion repetida, permisos por usuario, migracion sin perder datos, edicion atomica, conflictos, respaldos, restauracion y la condicion de caducidad. Las de navegador comprueban escritorio y movil, acceso, flechas, arrastre, movimiento por coordenadas, eliminacion de puntos, cancelacion, respaldos, restauracion, consentimiento y ajuste por tramos, reintento de guardado, captura GPS, bloqueo de pantalla, exportacion y cierre de sesion. Simulan Supabase, OSRM y Screen Wake Lock sin crear cuentas ni datos reales. Para instalar Chromium si falta, ejecuta `npx playwright install chromium`. La programacion real de pg_cron, la creacion de cuentas, el permiso GPS, Screen Wake Lock del telefono y las politicas en tu instancia requieren probarse en el dispositivo y Supabase reales.
